# Flashlet

A local-first coding workbench: browser UI → Node + Pi SDK → your OpenAI-compatible model server. No hosted model is configured by default.

## Quick start

Requires **Node.js 22.19+** and a model endpoint that supports **streaming Chat Completions or Responses and tool calls**. All application code, server modules, browser modules, build scripts, test fixtures and browser/integration tests are TypeScript. Strict type checking covers them all; no allowJs or ts-nocheck escape hatch. Browser JavaScript is generated by esbuild and is not committed.

```sh
npm ci
cp .env.example .env
# Set FLASHLET_WORKSPACE, FLASHLET_MODEL_BASE_URL and FLASHLET_MODEL_ID in .env
npm run dev
```

Open **http://127.0.0.1:3210**. Start your model server separately; Flashlet does not download weights or launch inference.

Example configuration for a compatible local server:

```dotenv
FLASHLET_WORKSPACE=/absolute/path/to/your/project
FLASHLET_MODEL_BASE_URL=http://127.0.0.1:8080/v1
FLASHLET_MODEL_ID=local-model
FLASHLET_CONTEXT_WINDOW=32768
FLASHLET_MAX_TOKENS=4096
FLASHLET_ALLOW_WRITES=false
# off | low | medium | high: show the model's reasoning (reasoning models only)
FLASHLET_THINKING=off
```

Use the model ID actually exposed by your server (`/v1/models` is often useful). FreeToken and llama.cpp are intended targets, but their model-specific tool-call templates and compatibility still need testing. There is no claim that every OpenAI-compatible endpoint supports agent tool calls. Match the context/output limits to the loaded model. If your server requires authentication, set `FLASHLET_MODEL_API_KEY` in `.env`. For a server on another machine, the configured endpoint can send code and prompts there, so choose it deliberately.

## What it does

- **Folders and chats.** Add any project directory as a folder; each chat runs with that folder as the agent's workspace. Chats are grouped under their folder in the sidebar.
- **Chats persist.** Every chat is saved as a Pi session file under `~/.flashlet/chats/<folder>/`. Refreshing the page or restarting the server keeps them; opening an old chat reads the file without starting an agent, and sending a message resumes it. Refreshing mid-answer replays the live turn.
- **Visible thinking.** With `FLASHLET_THINKING` set (or the composer's thinking selector), the model's reasoning streams into a collapsible "Thinking" block above the answer and is saved with the chat. Works with endpoints that stream `reasoning_content` (DeepSeek, Qwen3, llama.cpp).
- Stream chat responses over SSE and show Pi tool calls/results as cards with inputs and outputs.
- Cancel a running answer with Stop.
- Explore workspace files and preview text files up to 200 KB.
- View tracked working-tree changes against `HEAD`, with added/removed lines.
- Run Pi's actual agent loop in Node, not a browser-side imitation or CLI subprocess.
- Start read-only (`read`, `ls`, `find`, `grep`). Set `FLASHLET_ALLOW_WRITES=true` and restart to enable `bash`, `write`, and `edit`.
- Add MCP connectors over streamable HTTP or stdio, OAuth or API-key/custom headers.
- Render GFM markdown, highlighted code, KaTeX math, Mermaid diagrams and isolated static HTML/SVG artifacts.
- Use a responsive three-panel desktop layout and compact mobile chat/task switcher.

At most eight chats hold a live agent at once; the least recently used idle chat is released (it stays saved and reopens on the next message). An answer that is still running when the server stops is lost, but everything before it is saved. Folders are listed in `~/.flashlet/folders.json`; removing a folder only hides it, files on disk are never touched. This is a single-operator development tool, not a multi-user service.

## Safety boundaries

The HTTP server binds to `127.0.0.1`, validates Host/Origin, rejects cross-origin writes, and never sends the model API key to the browser. Do not expose it through a public proxy or tunnel. It has no login or remote-access security model.

**Pi tools are not sandboxed.** Read-only mode prevents tool-driven writes, not access to every sensitive file. Tools run with your OS permissions and may read paths outside the configured workspace. Write/shell mode can modify or execute anything your user can. Use a disposable checkout, container or restricted OS user for untrusted code/model output. Global pi CLI credentials, third-party extensions, skills and project instruction discovery are not loaded. Project MCP config is separate and opt-in through the trust control below. Only the explicitly bundled MCP, codemode, tool-search and permission extensions load. Model sessions are in-memory; connector credentials persist in a private data directory. This does not make model-generated tool calls safe.

The file browser rejects traversal/outside symlinks and hides `.env`, `.git`, common private-key files and dependency directories. Those are convenience protections, not a complete secret detector. Git diff omits `.env` and common private-key files; other tracked secrets could still appear. Do not select a workspace containing secrets. Model output uses sanitized markdown; raw HTML is escaped. Explicit artifact previews are isolated in a scriptless, network-disabled sandbox iframe.

## Architecture

```text
public/                index.html shell + style.css; generated JS in public/assets is gitignored
client/main.tsx        React app: TanStack Router (/f/:folder/c/:chat) + TanStack Query
client/useChat.ts      Chat state: saved transcript + live SSE (thinking, text, tools)
client/components/     Sidebar (folders/chats), Message, Composer, Inspector, Connectors, Modal
client/markdown.ts     Sanitized markdown, highlighting, KaTeX, Mermaid, artifact buttons
server/index.ts        Express, folder/chat API, session lifecycle, SSE, same-origin checks
server/folders.ts      Folder store (folders.json)
server/transcript.ts   Pi session messages -> UI blocks
server/agent.ts        Typed Pi SDK setup: per-folder cwd, persisted sessions, thinking level
server/files.ts        File preview and Git diff (tracked + new files)
server/config.ts       Environment validation
scripts/build.ts       esbuild browser bundle (npm run build)
```

The SDK is pinned to `@earendil-works/pi-coding-agent@1.4.0`. The `minimatch` and `undici` overrides select patched transitive versions; the real SDK integration tests run against those versions. Configuration stays server-side. Model adapters/endpoint tuning can be added without changing the UI transport.

## MCP connectors

Open **Connectors** in the top bar. Add Notion, Gmail, or any custom server. HTTP uses streamable HTTP (not legacy SSE). Stdio accepts one executable, JSON arguments and JSON environment variables. Commands are not shell strings. Installing/running a stdio server executes third-party code with your OS permissions. Only use servers you trust.

- **Gmail:** send/draft tools enabled by default, as requested. A per-connector **Read-only / Allow writes** switch restricts or enables them independently of local filesystem write mode. You can use your existing Gmail MCP URL or stdio command with the Gmail preset, or Custom MCP. The official Google URL is only a convenience preset, not the only Gmail path. Actual tools depend on your server: the official server currently offers draft creation but no send tool.
- **Notion/custom:** read-only by default. Only tools explicitly marked `readOnlyHint: true` run; unknown or mutation tools fail closed. To allow mutations, uncheck read-only AND enable `FLASHLET_ALLOW_WRITES=true` server-side. Server-provided hints are trusted metadata, not proof.
- **OAuth:** Sign in opens a link using pi's native OAuth implementation. Loopback callback completes automatically; if using another machine, paste the final redirected URL in the panel. Tokens refresh using pi. Sign out removes stored tokens; Remove also signs out. Existing task sessions may retain cached tokens/connections. Close old tasks to fully revoke in-memory access. Adding/enabling connectors applies to new tasks; permission restrictions and disabling also gate existing task calls.
- **API keys:** use Bearer token or Headers JSON (e.g. `{"X-API-Key":"${SERVICE_KEY}"}`). Environment variable references work server-side. Command interpolation (`!command`) is deliberately disabled in the panel. Never commit credentials.
- **Storage:** `~/.flashlet` by default, overridden with `FLASHLET_DATA_DIR`. Directory mode 0700; connector config and OAuth tokens mode 0600. Plaintext at rest, so protect your OS account/disk. The API does not return tokens, headers, client secrets or stdio env. Use a data directory outside your workspace/repo. Do not expose this localhost app through a tunnel.

Pi's own identity during OAuth is fine for this iteration. If a server needs a registered client, enter its client ID, secret, scope and callback port. Register the exact redirect `http://127.0.0.1:8765/callback` if using port 8765. OAuth brand comes from the authorization server/client registration, not the TypeScript SDK. Custom client naming is deferred.

**Official Google Gmail MCP caveat:** Google documents its endpoint as Developer Preview and requiring a Cloud project, enabled Gmail/Gmail MCP APIs and an agent-enabled OAuth client. It may require Preview access; this is not a claim that your existing pi Gmail MCP is blocked. Use the server you already use if different. Google's `access_type=offline` requirement is not currently exposed through pi 1.4.0's OAuth settings, so its refresh-token behavior needs a real account test. Notion and arbitrary Gmail implementations may have different requirements. No Google approval flow is needed just to use a different/self-hosted Gmail MCP that already works for you.

Email/documents/tool responses can contain prompt injection. The connector policy is a boundary, not a complete defense. Gmail write access allows actual sends if your server provides a send tool; review prompts carefully. There is no per-send confirmation dialog in this iteration. No real messages are sent by the tests.

## Generic model endpoint (Azure, local or other compatible hosts)

Use the same settings for any host. There is no Azure-specific provider or model dropdown:

```dotenv
FLASHLET_MODEL_BASE_URL=https://RESOURCE.openai.azure.com/openai/v1
FLASHLET_MODEL_ID=YOUR-DEPLOYMENT-NAME
FLASHLET_MODEL_API_KEY=YOUR-KEY
FLASHLET_MODEL_API=responses
FLASHLET_MODEL_AUTH_HEADER=bearer
# Leave blank for v1:
FLASHLET_MODEL_API_VERSION=
```

Use `FLASHLET_MODEL_API=completions` for llama.cpp/vLLM or compatible Chat Completions endpoints. `responses` selects `/responses`. The base URL is the API prefix, not the full operation path. For Azure v1, use `/openai/v1`, pass the deployment name as model, and omit `api-version`. Both bearer API-key auth and explicit `api-key` header are supported (`FLASHLET_MODEL_AUTH_HEADER=api-key`). Optional `FLASHLET_MODEL_API_VERSION` appends an `api-version` query parameter for compatible gateways. It does **not** automatically translate all legacy Azure deployment-specific routes. Entra automatic token refresh is not included. Keys remain in server environment only.

## Renderer

Markdown includes tables, lists, code highlighting and KaTeX. HTML in ordinary messages is escaped, then generated HTML is sanitized. Fenced `html`/`svg` blocks get a manual Preview artifact button. Artifacts are static only, with no scripts, network, forms, parent-page access or popups. Fenced `mermaid` blocks render on demand under strict security; exported SVG goes into the same sandbox. Arbitrary MCP Apps (`ui://` resources) are not rendered. Browser assets are built locally with esbuild; no CDN dependencies.

## Verification details and limits

Tests cover real pi SDK MCP stdio discovery, fail-closed tool-call hooks, OAuth DCR + PKCE loopback callback and persisted tokens against a local HTTP fixture, generic provider wire-level path/header/query/deployment behavior, plus the original chat/tool loop. Browser tests cover connector save, presets, mobile overflow, markdown/math/code, escaped raw HTML, and script-blocked artifact preview. `npm audit --omit=dev` is clean at implementation time.

Not yet tested against a real Gmail/Notion account, Azure deployment or local LFM/vLLM server. No RL/training changes. Pi's MCP token store classes are internal SDK modules in 1.4.0; a small pinned compatibility adapter supplies isolated auth/log paths because SDK defaults otherwise use global `~/.pi`. Upgrade that SDK only with the OAuth integration test passing. This PR does not enable arbitrary pi package installation or publish a pi package: the browser host and its explicit extension list remain controlled by this app.

## Native mcp.json editor and codemode

Open **Connectors > Edit mcp.json (global / project)**. The default global file is `FLASHLET_DATA_DIR/mcp.json` (normally `~/.flashlet/mcp.json`), isolated from the CLI's `~/.pi/agent/mcp.json`. The project file is `FLASHLET_WORKSPACE/.pi/mcp.json`. Both use pi's standard `{ "mcpServers": { ... } }` format. The form presets and global editor share that same global file; connector permission metadata stays private in the data directory.

Global config loads by default. A project config loads only after **Trust this project**, recorded through pi's ProjectTrustStore in the Flashlet data directory. Review commands and endpoints first: trusting a project can start local executables. Project entries replace global entries with the same name; partial enabled/exposure/toolExposure overrides use pi's native merge semantics. Revoke trust to stop new tool calls from project-only servers; close existing tasks to drop cached connections completely.

The editor validates JSON and the pinned SDK's native MCP schema before saving. It rejects colliding names, unsafe URLs, provider-credential forwarding and command interpolation. Project secret fields must use environment references, e.g. `${NOTION_TOKEN}`. Saved literal headers, env values, OAuth client secrets and command arguments are masked on reads with `__FLASHLET_SECRET_UNCHANGED__`; leave a mask untouched to retain its original value, or replace it with a new value. Ordinary secrets are never sent back to the browser. Revision checking rejects stale saves. Config symlinks are rejected. Save then start a new task; use the existing Sign in / Status / Reconnect buttons to authenticate configured servers.

`createCodemodeExtension({mode:"on",models:false})` is wired explicitly beside MCP and tool search. New form connectors default to `exposure:"codemode"`; the JSON editor can select codemode/deferred/direct/hidden and per-tool exposure. Pi runs scripts in its QuickJS sandbox and sends nested MCP calls through the same permission gate. The optional model-catalog bridge is disabled in codemode so scripts cannot invoke extra hosted models outside the configured chat endpoint. An integration test runs a real codemode script against an MCP fixture, reads a tool and confirms a mutation is blocked.

All source files (server, client, shared API types, build scripts, fixtures and browser tests) are TypeScript, with strict `tsc --noEmit`, no allowJs, no ts-nocheck and no explicit `any`. JavaScript under `public/assets` is generated browser output and is gitignored. The app still runs in Node through tsx; esbuild emits browser modules only.

Current local verification: nine backend/integration tests plus both browser suites, including native global/project config, masks, stale saves, project trust/revoke, schema validation, actual codemode execution, OAuth, streaming and provider wire tests. Real-service caveats above still apply.

Codemode reference: https://pi.dev/docs/latest/codemode
